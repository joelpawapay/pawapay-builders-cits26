# Refunds — returning a previously collected deposit

Refunds move funds from the merchant's pawaPay wallet back to the customer who paid. The refund references the original `depositId` — the customer's account details are inferred, not re-supplied.

## Endpoints

| Method | Path                                       | Purpose                              | Signed? |
|--------|--------------------------------------------|--------------------------------------|---------|
| POST   | `/v2/refunds`                              | Initiate a refund (full or partial)  | Yes     |
| GET    | `/v2/refunds/{refundId}`                   | Check status                         | No      |
| POST   | `/v2/refunds/fail-enqueued/{refundId}`     | Cancel an ENQUEUED refund            | No      |
| POST   | `/v2/refunds/resend-callback/{refundId}`   | Re-trigger the final-state callback  | No      |

## State machine

```
ACCEPTED → (ENQUEUED) → PROCESSING → (IN_RECONCILIATION) → COMPLETED | FAILED
```

Same as payouts/remittances — `ENQUEUED` happens when the provider is `DELAYED`.

## Initiate — POST /v2/refunds

### Request — full refund

```json
{
  "refundId": "f02b543c-541c-4f21-bbea-20d2d56063d6",
  "depositId": "afb57b93-7849-49aa-babb-4c3ccbfe3d79"
}
```

### Request — partial refund

```json
{
  "refundId": "f7232951-ab27-4175-bb63-6e15a9516df6",
  "depositId": "afb57b93-7849-49aa-babb-4c3ccbfe3d79",
  "amount": "30",
  "currency": "RWF",
  "clientReferenceId": "REFUND-001",
  "metadata": [ { "reason": "partial-not-shipped" } ]
}
```

### Field reference

- `refundId` (required) — UUIDv4, generated by the merchant. Idempotency key. Persist before calling.
- `depositId` (required) — the deposit being refunded. Must reference a deposit in `COMPLETED` state, not already fully refunded.
- `amount` (optional) — when omitted, refunds the remaining (un-refunded) balance of the deposit. When present, refunds exactly that amount.
- `currency` (required if `amount` is present) — must match the deposit's currency.
- `clientReferenceId` (optional) — merchant's reference. Returned in status-check (NOT in callbacks).
- `metadata` (optional) — same conventions as deposits/payouts.

**There is no `recipient` field.** The refund destination is implied from the original deposit. The customer's `phoneNumber`/`provider` are not re-specified.

### Response — 200

```json
{
  "refundId": "f02b543c-541c-4f21-bbea-20d2d56063d6",
  "status": "ACCEPTED",
  "created": "2025-05-15T07:38:56Z"
}
```

`status`: `ACCEPTED | REJECTED | DUPLICATE_IGNORED`.

### Failure code summary (initiation)

`NO_AUTHENTICATION, AUTHENTICATION_ERROR, AUTHORISATION_ERROR, HTTP_SIGNATURE_ERROR, INVALID_INPUT, MISSING_PARAMETER, UNSUPPORTED_PARAMETER, INVALID_PARAMETER, DUPLICATE_METADATA_FIELD, REFUNDS_NOT_ALLOWED, INVALID_AMOUNT, AMOUNT_OUT_OF_BOUNDS, INVALID_CURRENCY, PROVIDER_TEMPORARILY_UNAVAILABLE, PAWAPAY_WALLET_OUT_OF_FUNDS, NOT_FOUND, INVALID_STATE, AMOUNT_TOO_LARGE, DEPOSIT_ALREADY_REFUNDED, REFUND_IN_PROGRESS, UNKNOWN_ERROR`.

Refund-specific:

- `NOT_FOUND` — `depositId` does not exist on the account.
- `INVALID_STATE` — deposit is not in `COMPLETED` state (e.g. still processing, or failed).
- `AMOUNT_TOO_LARGE` — refund + previous-refunds exceeds deposit total.
- `DEPOSIT_ALREADY_REFUNDED` — the deposit's full amount has already been refunded.
- `REFUND_IN_PROGRESS` — another refund is already processing for this deposit. Only one refund per deposit at a time.

## Partial-refund semantics

A deposit can be refunded across multiple partial refunds:

- Each partial refund must specify `amount` and `currency`.
- The sum of all `COMPLETED` partial refunds must not exceed the original deposit amount.
- If a new refund (no `amount` specified) is initiated after partial refunds, it refunds the remaining balance only.

Example: original deposit `100 RWF`, partial refund `20 RWF`, partial refund `20 RWF`, then a refund without `amount` → refunds `60 RWF`.

After `DEPOSIT_ALREADY_REFUNDED`, no further refunds are accepted on that deposit.

## Check status — GET /v2/refunds/{refundId}

```json
{
  "status": "FOUND",
  "data": {
    "refundId": "...",
    "status": "COMPLETED",
    "amount": "30.00",
    "currency": "RWF",
    "country": "RWA",
    "recipient": { "type": "MMO", "accountDetails": { "phoneNumber": "...", "provider": "..." } },
    "customerMessage": null,
    "clientReferenceId": "REFUND-001",
    "created": "...",
    "providerTransactionId": "...",
    "failureReason": null,
    "metadata": { "reason": "partial-not-shipped" }
  }
}
```

`data.status`: `ACCEPTED, ENQUEUED, PROCESSING, IN_RECONCILIATION, COMPLETED, FAILED`.

`recipient` is populated from the original deposit's `payer`. Useful for support.

## Cancel enqueued — POST /v2/refunds/fail-enqueued/{refundId}

Same shape and semantics as payout fail-enqueued. Only valid while status is `ENQUEUED`. Lifecycle: `MANUALLY_CANCELLED` arrives in the callback.

## Resend callback — POST /v2/refunds/resend-callback/{refundId}

Same shape as other resend-callback endpoints. Refund must be in a final state.

## Lifecycle failure codes (during processing)

Set in `failureReason.failureCode` when `data.status = FAILED`:

- `PAWAPAY_WALLET_OUT_OF_FUNDS`
- `RECIPIENT_NOT_FOUND` — rare (the deposit succeeded so the account did exist; usually means the wallet was closed)
- `WALLET_LIMIT_REACHED` — the customer's wallet can't accept the refunded amount (e.g. monthly limit hit)
- `MANUALLY_CANCELLED`
- `UNSPECIFIED_FAILURE`
- `UNKNOWN_ERROR`

## Callback shape (refund webhook)

```json
{
  "refundId": "f02b543c-...",
  "status": "COMPLETED",
  "amount": "30.00",
  "currency": "RWF",
  "country": "RWA",
  "recipient": { "type": "MMO", "accountDetails": { "phoneNumber": "...", "provider": "..." } },
  "customerMessage": null,
  "created": "...",
  "providerTransactionId": "...",
  "failureReason": null,
  "metadata": {...}
}
```

`status` is the trimmed callback enum: `COMPLETED | PROCESSING | FAILED`. `clientReferenceId` is **not** in callbacks.

## Pitfalls specific to refunds

- **Trying to refund a `FAILED` or still-processing deposit.** Will return `INVALID_STATE`. Only `COMPLETED` deposits can be refunded.
- **Refunding more than what's left.** `AMOUNT_TOO_LARGE`. Track partial refunds locally to avoid bouncing.
- **Concurrent partial refunds on one deposit.** Only one at a time — `REFUND_IN_PROGRESS`. Serialise per-deposit refunds in your code.
- **Sending `currency` without `amount`.** Treated as a full refund anyway; `amount` is the trigger.
- **Forgetting refunds need wallet balance.** Refunds debit your pawaPay wallet. Insufficient balance → `PAWAPAY_WALLET_OUT_OF_FUNDS`.
- **Assuming refund hits the customer immediately.** Same lifecycle as payouts — including `ENQUEUED` during MMO downtime.

## Sample (Python)

```python
import uuid, requests, decimal

def refund_deposit(token, base, deposit_id, amount=None, currency=None, metadata=None):
    refund_id = str(uuid.uuid4())
    db.save_refund(refund_id, deposit_id=deposit_id, status="PENDING")

    body = {"refundId": refund_id, "depositId": deposit_id}
    if amount is not None:
        body["amount"] = str(amount)
        body["currency"] = currency
    if metadata:
        body["metadata"] = metadata

    try:
        r = requests.post(
            f"{base}/v2/refunds",
            headers={"Authorization": f"Bearer {token}"},
            json=body, timeout=10
        )
    except requests.RequestException:
        return _verify(token, base, refund_id)

    data = r.json()
    if data["status"] == "ACCEPTED":
        return {"refundId": refund_id, "state": "PENDING_CALLBACK"}
    if data["status"] == "DUPLICATE_IGNORED":
        return _verify(token, base, refund_id)
    db.update_refund(refund_id, status="FAILED", reason=data.get("failureReason"))
    return {"refundId": refund_id, "state": "FAILED", "reason": data.get("failureReason")}

def _verify(token, base, refund_id):
    r = requests.get(f"{base}/v2/refunds/{refund_id}",
                     headers={"Authorization": f"Bearer {token}"}).json()
    if r["status"] == "NOT_FOUND":
        db.update_refund(refund_id, status="FAILED", reason="never_reached_pawapay")
        return {"refundId": refund_id, "state": "FAILED"}
    return r["data"]
```
